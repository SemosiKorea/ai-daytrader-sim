# GPT 전체·사용자 선택 포트폴리오 비교실험

이 기능은 실제 주문과 분리된 세 개의 가상계좌에서 동일한 후보·시세·체결 모델을
비교합니다.

- `GPT_ALL_EQUAL`: GPT 후보 전체에 동일 목표비중을 부여하고 정수 주식으로 배분
- `USER_FIXED_SLEEVE`: 사용자 선택 종목만 GPT 전체 후보 수 기준 원래 몫을 유지
- `USER_REALLOCATED`: 사용자 선택 종목끼리 예수금을 동일 목표비중으로 재분배

## 고정 배분 규칙

배분은 승인된 최대 매수가와 예상 매수 비용으로 계산합니다. 최초 수량은
`floor(목표금액 / 1주 예상비용)`이며 소수점 주식은 만들지 않습니다.
`GPT_ALL_EQUAL`과 `USER_REALLOCATED`는 남은 현금으로 살 수 있는 종목 중 추가
1주 매수 후 목표비중 오차가 가장 작은 종목을 반복 선택합니다. 가장 저렴한
1주도 살 수 없는 잔액은 현금으로 남습니다. `USER_FIXED_SLEEVE`는 선택하지 않은
종목의 몫을 현금으로 유지하므로 잔액을 재분배하지 않습니다.

수량은 승인 시 고정됩니다. 어떤 종목이 진입하지 않거나 주문이 만료돼도 그 몫을
장중 다른 종목에 재분배하지 않습니다.

승인 시점의 초기자금, 수수료·슬리피지 설정, 목표비중과 계산 수량은 실험
메타데이터에 함께 고정 저장됩니다. 이후 `costs.yaml`을 변경해도 기존 실험의
배분과 체결 비용은 바뀌지 않습니다.

## 승인 및 생성

기존 텔레그램 OTP를 사용하며 한 OTP로 일반 계획과 비교실험을 동시에 등록할 수
없습니다.

```http
POST /v1/gpt-actions/experiments
Authorization: Bearer $GPT_ACTION_BEARER
```

요청에는 GPT 후보의 완전한 `CandidatePlan` 배열과 사용자가 진입 전에 선택한
`user_selected_symbols`를 포함합니다. 선택 목록은 후보의 부분집합이어야 하며
등록 후 변경할 수 없습니다.

## 저장 및 안전 경계

실험 메타데이터는 기본 DB에, 각 실험군 포트폴리오·주문·감사 로그는
`data/experiments/{experiment_id}/{cohort}.db`에 독립 저장됩니다. 앱 재시작 후
활성 실험을 복구합니다. 실험 브로커에는 KIS 주문 의도 기록기를 전달하지 않으므로
실제 주문 및 KIS 주문 요청 기록을 만들지 않습니다.

## 결과 조회

```http
GET /v1/gpt-actions/experiments/{experiment_id}
Authorization: Bearer $GPT_ACTION_BEARER
```

응답에는 실험군별 목표비중·정수 수량·예상 잔액, 현재 포트폴리오, 순손익,
Profit Factor, 미실현손익을 포함한 평가금액 기준 최대 낙폭과 종목별 결과가
포함됩니다. 비교 항목은 다음과 같습니다.

- 사용자 원래비중 유지 손익 - GPT 전체 손익
- 사용자 재분배 손익 - GPT 전체 손익
- 재분배 손익 - 원래비중 유지 손익
- GPT 전체 계좌에서 선택 종목과 제외 종목의 거래당 평균손익 차이
- GPT 전체 계좌에서 선택 종목과 제외 종목의 거래당 평균수익률 차이

실험 주문의 만료와 장 마감 청산은 기본 계좌와 같은 정기 스케줄러가 관리합니다.
시세 연결이 끊겨 정규장 안에 청산하지 못하면 공식 장 종료 후 저장된 마지막
정규장 bid로 복구 청산하고 그 사유를 감사 로그에 남깁니다.
