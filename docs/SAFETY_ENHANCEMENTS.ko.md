# 보완사항 구현 대조표

## 프로그램 내부에 구현된 항목

| 보완사항 | 구현 내용 |
|---|---|
| 신호와 체결 분리 | `SIGNAL_TRIGGERED → ENTRY_PENDING → PARTIALLY_FILLED/FILLED → POSITION_OPEN` 상태와 감사 이벤트 |
| 지연·부분체결 | 시장별 설정 지연 후 체결, 호가 잔량 또는 거래량 참여율 제한, Tick당 최대수량, 제한시간 만료 |
| 매도 체결 | 손절·익절·시간청산도 지연 후 bid 잔량 범위에서 부분체결, 장 종료 후에만 마지막 저장 호가 복구 사용 |
| 시장 슬롯 예약 | `ENTRY_PENDING`부터 시장 슬롯 점유, 취소·만료 때 해제 |
| 주문 횟수 | 주문 제출 횟수와 최초 부분체결 기준 진입 횟수를 별도로 관리 |
| 보수적 손절 | `bid`로 손절 트리거, 시장성 지정가 하단과 비상 청산 제한시간 분리 |
| 최악가격 손익비 | 최대 지정가, 수수료, 세금, FX, 슬리피지 및 예상 손절 체결가를 반영해 1.5 이상 검증 |
| 위험기준 수량 | 거래당 위험예산, 일일 잔여 위험예산, 현금, 종목 최대수량 중 최솟값 |
| 일일 총위험 | 당일 실현손실 + 보유 포지션 예상 손절손실 + 미체결 주문 예정위험 |
| 데이터 무결성 | 원천·수신 시각, 미래·역행 시각, 시퀀스 역행, crossed/locked 호가, 스프레드 검사 |
| 세션 구분 | 정규장만 신규 진입, 미국은 확인된 통합호가만 허용 |
| 거래중단 | 시장·종목·LULD 상태가 정상이 아니면 대기 주문 취소 및 신규 진입 금지 |
| 복구 워밍업 | 연결 ID·세션 변경과 거래 재개 때 교차 상태 초기화 및 재진입 대기 |
| 교차 디바운스 | 확인 Tick, 유지시간, 최소 돌파폭, Cooldown 지원 |
| 지표 준비 상태 | 지표별 ready와 생성 시각 필수, 1분봉·정적 지표별 별도 유효시간 |
| 시가 범위 | N분 범위가 완성되기 전 시작하는 계획 거절 및 ready 필수 |
| 동적 장 종료 | 공식 거래소 달력으로 휴장·서머타임·조기폐장 반영 |
| 시간 청산 | 최대 보유시간, 진행 부진, VWAP 이탈 청산 |
| 익절 후 관리 | 선택적으로 1차 익절 후 손절을 진입가격으로 이동 |
| 논리 검증 | 빈 규칙, 중복 목표, 모순 범위, 미지원 지표, 깊이·개수 위반 거절 |
| 계획 무결성 | 계획 버전, 생성·만료시각, 승인 Hash, 수정 계획 버전 증가, 실행 중 교체 금지 |
| 중복 방지 | `plan_id:symbol:ENTRY` 멱등성 키를 SQLite에서 원자적으로 선점 |
| 기업행동 | 피드가 `corporate_action=true`를 보내면 계획 무효화 및 가능한 가상 청산 |
| 의사결정 로그 | 진입 거절, 데이터 거절, 주문 상태, 체결, 취소, 계획 상태를 사유코드와 Snapshot으로 저장 |
| 눌림목 재돌파 | 최초 돌파·ATR 눌림·거래량 감소·눌림 고점 재돌파를 영속 상태 머신으로 판정 |

## 외부 확장 피드가 제공해야 하는 항목

프로그램은 다음 정보를 스스로 추정하지 않습니다. 검증된 시세 브리지가 실제
데이터를 제공해야 안전 규칙이 작동합니다.

- 미국 통합호가 여부
- 거래소 원천 시각, 수신 시각 및 단조 증가 시퀀스
- 정규장·프리마켓·시간외 세션 구분
- 시장 및 종목 거래중단, LULD 상태와 중단 사유
- 기업행동 감지 및 조정된 전일 가격
- `INDICATOR_CONTRACT.ko.md` 정의에 맞는 지표, 준비 상태, 생성 시각

KIS REST 보조 폴러는 통합호가·거래중단·확장 지표를 확정할 수 없으므로 가격
조회 보조 용도입니다. 지연 민감 가상매매의 주 시세원으로 간주하지 않습니다.

## 아직 선택 기능으로 남은 항목

- 실적 발표·거시지표 발표 등 이벤트 데이 자동 필터
- ATR 기반 추적손절
- 주문장 여러 단계와 큐 순서를 반영한 고급 체결 모델
- 동일 섹터 종목 사이의 연속 손절 차단
- 실시간 실행과 과거 재생 결과의 자동 괴리 분석

이 항목들은 기본 안전 경계를 약화하지 않으며, 신뢰할 수 있는 추가 데이터가
준비된 뒤 별도 검증을 거쳐 활성화해야 합니다.
